# Themes for the companion app, from a build-time themes.toml

## 1. Goal

The companion's colours are constants spread over nine files, and there is
one look: dark gray. After this plan, a theme is a named set of colour
roles in one TOML file. The app draws every screen from the theme in force,
and the settings' Display section has a *Theme* row that switches it at
once.

## 2. Decisions

1. **Roles, not constants.** A theme defines every role, each `#RRGGBB` or
   `#RRGGBBAA`:
   - **surfaces:** `bg`, `header`, `card`, `band`, `input`, `overlay`;
   - **text:** `text`, `dim`, `muted`, `code`, `link`, `spoken`;
   - **states:** `accent`, `green`, `red`, `yellow`, `warn`, `recording`;
   - **buttons:** `approve`, `deny`, `message`, `back`, `button`;
   - **chrome:** `scrollbar`, `placeholder`, `shimmer`, `shadow`.

   Each of today's 32 constants maps to one role. Where two constants are
   the same colour in every theme, they share a role.
2. **`apps/companion/themes.toml`:** one table per theme.

   ```toml
   [theme.dark_gray]
   name = "Dark (gray)"
   dark = true          # for the system bars' icons
   bg = "#1A1C24"
   text = "#F0F2F5"
   # … every role
   ```

   `build.rs` reads it with the `toml` crate and generates `themes.rs`:
   - one `Theme` constant per table, with its colours as `[f32; 4]`;
   - `THEMES` in file order.

   The build fails when a role is missing, a value isn't a colour, or two
   themes share an id. The first theme is the default.
3. **The themes shipped,** in this order:
   - *Dark (gray)*: today's colours, exactly;
   - *Dark (black)*: true black surfaces, for OLED;
   - *Dark (navy)*: the icon's `#0F0F26`, with magenta accents;
   - *Light (black text)*: white surfaces, black text;
   - *Light (paper)*: warm off-white, dark brown-gray text;
   - *Solarized Dark* and *Solarized Light*: Ethan Schoonover's palette
     (base03…base3, with yellow, orange, red, magenta, violet, blue, cyan
     and green as accents);
   - *Gruvbox Dark*, *Nord*, *Dracula* and *Tokyo Night*: their published
     palettes, mapped onto the roles;
   - *High contrast*: black and white, with saturated accents.

   Each palette's source is named in a comment in `themes.toml`.
4. **One theme in force.**
   - A `theme()` accessor returns the current `&'static Theme`, held in a
     thread-local like the settings.
   - Every drawing site reads its colours from it, in place of the
     constants, including the Markdown runs, libcontrols' modal frames and
     the `ArrowLabel` and toggle colours the settings pass in.
   - Changing it marks every screen dirty, so the next frame is in the new
     theme. Laid-out blocks whose colours are baked into their rows are
     laid out again.
5. **The *Theme* row:**
   - in the Display section, after *Scrollbar*, on `ArrowLabel` (‹ Dark
     (gray) ›);
   - it steps through `THEMES` in file order, wrapping, and applies each
     step at once;
   - it is saved as `theme = "<id>"` in `settings.toml`. An unknown id is
     the default;
   - its label comes from `SETTINGS_COPY.md`, and its values from the
     themes' names.
6. **The system bars** follow the theme's `dark` flag (light or dark
   icons), if libmorph offers a way. Otherwise they stay as they are, and
   it is noted.

## 3. Steps

1. **`themes.toml` and its build-time check,** generating `themes.rs`, with
   *Dark (gray)* equal to today's constants.
   **Done when:** a test shows every constant's value equals *Dark (gray)*'s
   role; the build fails for a missing role and a bad colour (tested
   through the generator's own unit tests, as `copy_gen.rs` is).
2. **The constants replaced by `theme()`,** in all nine files.
   **Done when:** the app's tests pass unchanged under *Dark (gray)*, and a
   test that switches to *Light (black text)* finds no drawn instance still
   in a dark-theme colour on the overview, the agent view and settings.
3. **The *Theme* row,** saved and restored.
   **Done when:** tests step it both ways with wrapping, apply each step
   at once, and keep it across a save and load; and on the S23, every
   theme looks right on the overview, the agent view and settings.

Each step is one commit to the app (Rule 3.1). 2 needs 1; 3 needs 2.
